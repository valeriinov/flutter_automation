flutter_automation

A set of packages for Flutter apps. An AI agent or a developer runs the app on a phone or a simulator. One command then walks a user journey through it and returns a report. Набір пакетів для застосунків на Flutter. AI-агент або розробник запускає застосунок на телефоні чи симуляторі. Потім одна команда проходить шлях користувача і повертає звіт.

The idea in one minuteІдея за одну хвилину

  • A tester usually opens the app and taps through a screen by hand. These packages let a program do the same taps.Тестувальник зазвичай відкриває застосунок і проходить екран руками. Ці пакети дають програмі зробити ті самі натискання.
  • The journey is written down once, for example "sign in and open the catalog". After that, one command repeats it on any device.Шлях записують один раз, наприклад «увійти і відкрити каталог». Далі одна команда повторює його на будь-якому пристрої.
  • The app needs no real server for this. A built-in fake server puts the app into the state that the journey needs.Справжній сервер для цього не потрібен. Вбудований фейковий сервер ставить застосунок у стан, потрібний шляху.
  • The result is a report: which steps passed and how many milliseconds each one took.Результат — звіт: які кроки пройшли і скільки мілісекунд зайняв кожен.

The path of one runШлях одного запуску

1JourneyШляхThe steps: tap, wait, type.Кроки: натиснути, дочекатися, ввести.
2StateСтанFor example: an empty list, or a server error.Наприклад: порожній список або помилка сервера.
3RunnerРаннерSends the state and the steps to the app.Надсилає стан і кроки в застосунок.
4 · on the device4 · на пристроїAppЗастосунокDoes the steps. The fake server answers its requests.Виконує кроки. Фейковий сервер відповідає на запити.
5ReportЗвітPassed or failed, and the time of each step.Пройшло чи ні, і час кожного кроку.

What it gives the teamЩо це дає команді

No server neededБез сервера

The mock shows any state on demand: an empty list, an error, a slow network. Nobody prepares test data on a remote environment.Мок показує будь-який стан на вимогу: порожній список, помилку, повільну мережу. Нікому не треба готувати тестові дані на віддаленому середовищі.

Same result every timeТой самий результат щоразу

A flow names its state. Each run starts from that state, so two runs compare fairly.Флоу називає свій стан. Кожен запуск стартує з цього стану, тому два запуски чесно порівнюються.

Text changes break nothingЗміна тексту нічого не ламає

Steps find elements by target. A new button label or a translation does not break a flow.Кроки знаходять елементи за таргетом. Новий напис на кнопці чи переклад не ламає флоу.

A number, not an impressionЧисло, а не враження

The report gives milliseconds per step. "The screen got slower" becomes a measured fact.Звіт дає мілісекунди на кожен крок. «Екран став повільнішим» стає виміряним фактом.

Any languageБудь-яка мова

One option runs the same flow in another language of the app.Одна опція проганяє той самий флоу іншою мовою застосунку.

Safe for usersБезпечно для користувачів

The store build holds none of this code. A build switch removes it.Збірка для магазину не містить цього коду. Перемикач збірки прибирає його.

"Show the empty catalog on the device"«Покажи порожній каталог на пристрої»Sets the mock to that state and runs the app.Ставить мок у цей стан і запускає застосунок.

How it fits into a projectЯк це вбудовується в проєкт

  1. Connect onceПідключити один раз

    A developer or the agent adds the packages. This takes one request to the agent.Розробник або агент додає пакети. Агенту для цього достатньо одного запиту.

  2. Mark the screensРозмітити екрани

    Each screen of a journey gets targets on the elements a step must reach.Кожен екран шляху отримує таргети на елементах, до яких має дістатися крок.

  3. Describe the journeysОписати шляхи

    A flow per journey, a variant per case: the happy path, an empty list, an error.Флоу на кожен шлях, варіант на кожен випадок: успішний шлях, порожній список, помилка.

  4. Run and read the reportЗапустити і прочитати звіт

    Any person or agent repeats a journey with one command, after every change.Будь-яка людина чи агент повторює шлях однією командою після кожної зміни.

For the store build:Для збірки в магазин: nothing changes. The automation code works only in a debug or profile build that turns it on.нічого не змінюється. Код автоматизації працює лише в debug- або profile-збірці, яка його вмикає.

You need:Потрібно: a Flutter project, and an Android emulator, an iOS simulator or a phone on a cable. The agent route also needs Claude Code, Codex or another agent with skills.проєкт на Flutter, а також емулятор Android, симулятор iOS або телефон на кабелі. Для шляху з агентом також потрібен Claude Code, Codex або інший агент зі скілами.

  name: 'home',

      const WaitFor(ByTarget(HomeTarget.screen)),
      const Tap(ByTarget(HomeTarget.increment)),

The mockМок

  1. Declare a sectionОголосити секцію

    One MockSection per backend area, in a host-safe file. The settings class needs fromJson, toJson and copyWith. A profile is a function over the settings, so each key is written once.Одна MockSection на кожну частину бекенду, у файлі, безпечному для хоста. Клас налаштувань потребує fromJson, toJson і copyWith. Профіль — це функція над налаштуваннями, тому кожен ключ записано один раз.

    import 'package:flutter_automation_mock/mock_section.dart';

final catalogSection = MockSection<CatalogSettings>(
  name: 'catalog',
  fromJson: CatalogSettings.fromJson,
  profiles: {
    'emptyShelf': (settings) => settings.copyWith(itemCount: 0),
    'fullShelf': (settings) => settings.copyWith(itemCount: 5),
  },
