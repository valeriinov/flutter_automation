flutter_automation

A set of packages for Flutter apps. An AI agent or a developer runs the app on a phone or a simulator. One command then walks a user journey through it and returns a report. Набір пакетів для застосунків на Flutter. AI-агент або розробник запускає застосунок на телефоні чи симуляторі. Потім одна команда проходить шлях користувача і повертає звіт.

The idea in one minuteІдея за одну хвилину

  • A tester usually opens the app and taps through a screen by hand. These packages let a program do the same taps.Тестувальник зазвичай відкриває застосунок і проходить екран руками. Ці пакети дають програмі зробити ті самі натискання.
  • The journey is written down once, for example "sign in and open the catalog". After that, one command repeats it on any device.Шлях записують один раз, наприклад «увійти і відкрити каталог». Далі одна команда повторює його на будь-якому пристрої.
  • The app needs no real server for this. A built-in fake server puts the app into the state that the journey needs.Справжній сервер для цього не потрібен. Вбудований фейковий сервер ставить застосунок у стан, потрібний шляху.
  • The result is a report: which steps passed and how many milliseconds each one took.Результат — звіт: які кроки пройшли і скільки мілісекунд зайняв кожен.

The path of one runШлях одного запуску

1JourneyШляхThe steps: tap, wait, type.Кроки: натиснути, дочекатися, ввести.
2StateСтанFor example: an empty list, or a server error.Наприклад: порожній список або помилка сервера.
3RunnerРаннерSends the state and the steps to the app.Надсилає стан і кроки в застосунок.
4 · on the device4 · на пристроїAppЗастосунокDoes the steps. The fake server answers its requests.Виконує кроки. Фейковий сервер відповідає на запити.
5ReportЗвітPassed or failed, and the time of each step.Пройшло чи ні, і час кожного кроку.

What it gives the teamЩо це дає команді

No server neededБез сервера

The mock shows any state on demand: an empty list, an error, a slow network. Nobody prepares test data on a remote environment.Мок показує будь-який стан на вимогу: порожній список, помилку, повільну мережу. Нікому не треба готувати тестові дані на віддаленому середовищі.

Same result every timeТой самий результат щоразу

A flow names its state. Each run starts from that state, so two runs compare fairly.Флоу називає свій стан. Кожен запуск стартує з цього стану, тому два запуски чесно порівнюються.

Text changes break nothingЗміна тексту нічого не ламає

Steps find elements by target. A new button label or a translation does not break a flow.Кроки знаходять елементи за таргетом. Новий напис на кнопці чи переклад не ламає флоу.

A number, not an impressionЧисло, а не враження

The report gives milliseconds per step. "The screen got slower" becomes a measured fact.Звіт дає мілісекунди на кожен крок. «Екран став повільнішим» стає виміряним фактом.

Any languageБудь-яка мова

One option runs the same flow in another language of the app.Одна опція проганяє той самий флоу іншою мовою застосунку.

Safe for usersБезпечно для користувачів

The store build holds none of this code. A build switch removes it.Збірка для магазину не містить цього коду. Перемикач збірки прибирає його.

How it fits into a projectЯк це вбудовується в проєкт

  1. Connect onceПідключити один раз

    A developer or the agent adds the packages. This takes one request to the agent.Розробник або агент додає пакети. Агенту для цього достатньо одного запиту.

  2. Mark the screensРозмітити екрани

    Each screen of a journey gets targets on the elements a step must reach.Кожен екран шляху отримує таргети на елементах, до яких має дістатися крок.

  3. Describe the journeysОписати шляхи

    A flow per journey, a variant per case: the happy path, an empty list, an error.Флоу на кожен шлях, варіант на кожен випадок: успішний шлях, порожній список, помилка.

  4. Run and read the reportЗапустити і прочитати звіт

    Any person or agent repeats a journey with one command, after every change.Будь-яка людина чи агент повторює шлях однією командою після кожної зміни.

For the store build:Для збірки в магазин: nothing changes. The automation code works only in a debug or profile build that turns it on.нічого не змінюється. Код автоматизації працює лише в debug- або profile-збірці, яка його вмикає.

What the QA panel gives youЩо дає QA-панель

The QA panel is a screen inside a test build of the app. It talks to a fake server, the mock, and not to the real backend. With it you put the app into any state in a few taps, walk a user journey step by step or let the app walk it by itself, and send a report of the run to the developers.QA-панель — це екран усередині тестової збірки застосунку. Вона працює з фейковим сервером, моком, а не зі справжнім бекендом. З нею ви за кілька натискань ставите застосунок у будь-який стан, проходите шлях користувача крок за кроком або даєте застосунку пройти його самому і надсилаєте розробникам звіт прогону.

  • The mock answers every request of the app the way the real server does. You decide what it answers: a normal answer, an error, or no network.Мок відповідає на кожен запит застосунку так, як справжній сервер. Ви вирішуєте, що він відповідає: звичайну відповідь, помилку або відсутність мережі.
  • A flow is one user journey, for example "sign in". An outcome is one ending of a flow, for example "sign-in with a wrong code".Флоу — це один шлях користувача, наприклад «вхід». Результат (outcome) — один із фіналів флоу, наприклад «вхід з неправильним кодом».
  • A walk is a run of a flow that you lead: the app does one step per tap of Next step. An autorun is a run that the app does from start to end by itself.Прохід (walk) — прогін флоу, яким керуєте ви: застосунок робить один крок за натискання Next step. Автопрогін (autorun) — прогін, який застосунок робить від початку до кінця сам.
  • An override is an answer you set for one request, for example "error 500 on /auth/login". It stays until you remove it or tap Reset.Підміна (override) — відповідь, яку ви задали одному запиту, наприклад «помилка 500 на /auth/login». Вона діє, доки ви її не приберете або не натиснете Reset.
  • The panel text is English only. This page names each button as the panel shows it.Текст панелі лише англійською. Ця сторінка називає кожну кнопку так, як її показує панель.

  1. Install the test buildВстановити тестову збірку

    The developers give you a test build. A store build has no QA panel.Тестову збірку дають розробники. У збірці з магазину QA-панелі немає.

  2. Open the debug menu of the appВідкрити меню налагодження застосунку

    Each project opens it in its own way. Ask the developers of your project how.Кожен проєкт відкриває його по-своєму. Спитайте в розробників свого проєкту, як саме.

  3. Turn on Mock modeУвімкнути Mock mode

    The app restarts. On some devices it closes: open it again. The app now talks only to the mock.Застосунок перезапускається. На деяких пристроях він закривається: відкрийте його знову. Тепер застосунок працює лише з моком.

  4. Find the QA buttonЗнайти кнопку QA

    A round QA button stands over the app. Drag it to any place where it does not cover what you test. A tap on it opens the panel.Над застосунком з'являється кругла кнопка QA. Перетягніть її туди, де вона не закриває те, що ви тестуєте. Натискання на неї відкриває панель.

A

Walk a flow step by stepПройти флоу крок за кроком

Use a walk to look at each screen of a journey, to try a branch by hand or to repeat a bug.Прохід підходить, щоб роздивитися кожен екран шляху, спробувати гілку вручну або повторити баг.

  1. Open the flowВідкрити флоу

    On the Flows tab, type a part of the name in the search field and tap the flow.На вкладці Flows введіть частину назви в поле пошуку і натисніть на флоу.

  2. Read the flow mapПрочитати мапу флоу

    The map shows the start screen (Start:), each step with the requests it sends, the fork where the flow splits into branches and the ending (Result:).Мапа показує стартовий екран (Start:), кожен крок із запитами, які він надсилає, розвилку, де флоу ділиться на гілки, і фінал (Result:).

  3. Change an answer, if you need toЗмінити відповідь, якщо потрібно

    Tap a request on the map to give it an error or no network. When a branch of the fork needs another start state, the map lets you pick that branch here, before the start.Натисніть на запит на мапі, щоб дати йому помилку або відсутність мережі. Коли гілці розвилки потрібен інший стартовий стан, мапа дає обрати цю гілку тут, до старту.

  4. Tap Restart and beginНатиснути Restart and begin

    The app restarts. Open it again if it closed. The walk begins on the start screen of the flow.Застосунок перезапускається. Відкрийте його знову, якщо він закрився. Прохід починається зі стартового екрана флоу.

  5. Tap Next stepНатискати Next step

    A plaque stands over the app. Collapsed, it shows the flow, the step such as 3/10 and a round button that does the next step. Tap the plaque to open it: it then shows the next action in words and a Next step button. Drag the plaque by its head to move it.Над застосунком з'являється плашка. Згорнута, вона показує флоу, крок, наприклад 3/10, і круглу кнопку, яка робить наступний крок. Натисніть на плашку, щоб розгорнути: тоді вона показує наступну дію словами і кнопку Next step. Перетягуйте плашку за шапку.

  6. Choose a branch at the forkОбрати гілку на розвилці

    At the fork the plaque shows Choose the branch. Tap a branch, then Next step. The walk goes on in that branch.На розвилці плашка показує Choose the branch. Натисніть на гілку, потім Next step. Прохід іде далі цією гілкою.

  7. Tap FinishНатиснути Finish

    When no action is left, the button reads Finish. It does the waits that are left and opens the run summary.Коли дій не лишилося, кнопка показує Finish. Вона виконує очікування, що лишилися, і відкриває підсумок прогону.

While a walk runs, the app takes no taps.Поки йде прохід, застосунок не приймає натискань. Only the plaque and the QA button take your finger, and the system back button does nothing. The keyboard still types. To take the app back, tap the cross on the collapsed plaque or Exit on the open one: the app stays on its screen.Пальця слухаються лише плашка і кнопка QA, а системна кнопка «назад» нічого не робить. Клавіатура й далі вводить текст. Щоб повернути собі застосунок, натисніть хрестик на згорнутій плашці або Exit на розгорнутій: застосунок лишається на своєму екрані.

A step failed?Крок не вдався? The plaque shows the reason in red and the button reads Try again. Tap it to do the step again, or tap Exit and report the reason.Плашка показує причину червоним, а кнопка — Try again. Натисніть її, щоб повторити крок, або натисніть Exit і повідомте причину.

    Show touches draws a circle where the app taps. Signal at the end vibrates and plays a sound when the run ends.Show touches малює коло там, де застосунок натискає. Signal at the end вібрує і грає звук, коли прогін закінчується.

  4. Tap Restart and runНатиснути Restart and run

C

Make the server answer with an errorЗмусити сервер відповісти помилкою

Use it to check error screens, toasts and retries. An override stays until you remove it, also after a restart.Так перевіряють екрани помилок, тости і повтори. Підміна діє, доки ви її не приберете, також після перезапуску.

  1. Find the requestЗнайти запит

    On the Log tab, tap the request the app sent, or on the Sections tab, open Requests of a section. The search finds a request by a part of its path.На вкладці Log натисніть на запит, який надіслав застосунок, або на вкладці Sections відкрийте Requests розділу.   2. Choose the answerОбрати відповідь

    The Response sheet opens. Pick an Error code, if you need a Backend error code and a Message. Or pick No network: the request then never reaches the server.Відкривається аркуш Response. Оберіть Error code, за потреби Backend error code і Message. Або оберіть No network: тоді запит не доходить до сервера.

  3. Tap ApplyНатиснути Apply

    The request row shows the override in red, and the status row counts it. Repeat the action in the app to see the error.Рядок запиту показує підміну червоним, а рядок стану її рахує. Повторіть дію в застосунку, щоб побачити помилку.

  4. Remove the overrideПрибрати підміну

    Tap the cross on the request row, or Use mock response in the sheet. Reset removes every override at once.Натисніть хрестик у рядку запиту або Use mock response в аркуші. Reset прибирає всі підміни одразу.

Profile of a sectionПрофіль розділуOn the Sections tab, tap Profile in a section and pick a ready state, for example a user who must finish the sign-up. A section shows Default with no setting and Custom when its settings match no profile. A profile marked ⟳ Restarts the app takes effect after a restart: the panel asks for it.На вкладці Sections натисніть Profile у розділі й оберіть готовий стан, наприклад користувача, який має завершити реєстрацію.
